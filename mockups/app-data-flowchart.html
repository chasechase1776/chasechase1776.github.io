Current app understanding

Homeschool Activity Data Flow

The activity record is the source of truth. The parent logs what happened once, and the app derives subject time, legal coverage, skills, reviews, and exports from that saved activity data.

UI input Database source Parent review Generated export

1. Parent Daily Log

Fast entry first. Details are optional and can be opened only when needed.

Persistent Context

Student, school year, school-year status, official start date, and current unit study stay pinned while the parent logs.

Date + Activity Type

Activity type buttons work as both selectors and daily completion indicators.

  • Neutral: no record yet
  • Yellow: draft or needs review
  • Green: approved activity exists
  • Blue: currently selected

Minimal Valid Record

The parent can save a real record with title, date, activity type, actual minutes, and narration.

Optional Details

Proof, legal tags, skills, notes, unit details, and subject metadata should be progressively disclosed.

2. Server + Database

Manual logging must work without AI. The database is the permanent source of truth.

POST /api/activities

Saves draft or approved activities with student, school year, unit, date, type, narration, minutes, legal tags, and subject allocation.

Subject Allocation Rule

Allocated subject minutes must equal actual activity minutes. One 30-minute activity can touch multiple concepts, but the clock time is counted once.

GET /api/activities?date=...

Loads saved records for the selected date. Button states are calculated from these records, not manually reset.

Prisma/Postgres Models

Activity connects to student, school year, unit study, subject allocations, legal tags, skills, and evidence artifacts.

3. Review + Outputs

Reports and files are generated from database records after parent approval or review.

AI Parse Drafts

AI can suggest draft cards from narration, but it cannot create permanent approved records until the parent saves them.

Weekly + Quarter Reviews

Reviews should pull approved activities, subject time, legal tags, skills, artifacts, and parent notes from saved records.

Markdown Snapshots

Daily records, weekly summaries, unit files, skills-covered files, legal summaries, and portfolio indexes are regenerated from database data.

PDF / Portfolio Exports

PDFs are readable archives for review, legal records, and long-term backup. They are not the primary data store.

UX simplification rules

What should stay visible vs. collapse

Always visible Date, activity type, title, actual minutes, narration, Save Draft, Save Approved.
Collapsed by default Legal tag editing, skills, standards, evidence details, notes, reports, review summaries.
Visible but quiet Texas coverage status, weekly subject time, and activity completion indicators.

Compliance guardrails

Simplify without losing records

Do not remove Legal tags, subject allocations, skills, evidence, reviews.
Do hide complexity Show it only when the parent needs to review or edit it.
Do preserve Database as source of truth; Markdown/PDF as exports.
